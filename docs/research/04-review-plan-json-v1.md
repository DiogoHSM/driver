# Review 04: plan.json v1 (adversarial, step 5)

**Verdict: fix first.** The core (reducer, store, lock, rotation, schema) holds up. `npm test` (229 tests), `tsc --noEmit` and `claude plugin validate .` all pass, and 24 parallel `block add` processes produced rev 24, 24 blocks, 24 events, and a clean `validate --replay`. The problems are in what the user-only and protection guarantees rest on, one ADR contradiction that blocks Evolve, and git root resolution.

Evidence was gathered in the session scratchpad. `h '<cmd>'` means piping a Bash tool payload into `node dist/cli.js hook protect-plan`.

## Accepted risks (would not fix in v1)

- **Marker trust.** DRIVER-BLOCK is self-declared. During discover an untagged Agent is always allowed, and the invariant `phase>discover ⇒ route approved` means the route check without a marker never denies. The gate stops only honest mis-sequencing, so the skills must always tag their prompts. Agents spawned inside a Workflow script do not go through the `Agent` hook.
- **The protect hook needs `node`.** If node is missing, the hook command fails as a non-blocking error and the hook fails open. Gate-check has the jq fallback and fails closed. This matches the ADR's stated consequence.
- `cd` plus relative paths, and arbitrary interpreters, cannot be closed with regexes. `validate --replay` and git history detect what slips through.
- **Crash between `writePlan` and `appendEvents`.** This leaves a revision with no event, and `--replay` reports `replay.mismatch` until that block transitions again. A crash during rotation self-heals (`lastSeq` falls back to `log/`). There is no `repair` command yet.
- **Rare lock and git edge cases.** If putting back a lock moved aside fails, two writers can hold it, and a reused pid looks like a live owner (both need a crash plus a race). Git older than 2.31 falls back to cwd. `merge=union` can duplicate seq values when two clones merge. Also: `--now` and `--actor hook:x` can be forged, and directories are not fsynced.
- **Extensibility is fine.** `looseObject` plus `sortKeys` preserves unknown fields through a write (checked: `blocks.B-001.estimate` and a top-level `futureTop` survived a `block.add`). `estimate`, `parent`/`epics` and `impact` need no version bump. The future mod already has what it needs: `revision` for change detection, `phase` per block, `retired`, and `owner`.

## Untested behaviour

- Protect-plan: no corpus of bypasses (quoting, `cd` plus relative paths, interpreters, `git checkout`, `./` and `//` paths) or of false positives.
- `block.set` with keys outside the whitelist. `req add` in evolve. Retiring before Gate 1. Resuming after `phase back`.
- `resolveProjectRoot` in submodules, in bare repos, and from a subdirectory of a linked worktree.
- SubagentStop with a realistic `agent_id`. Gate-check with no `git`. Mermaid through a real parser. Crash injection between rename, append and rotation. `--expected-revision` is not exposed by the CLI either.
- Flakiness: the lock tests rely on a "dead" pid (could be reused, low risk). The multi-process tests have a 5 s lock timeout and can time out on slow CI.

**Updated verdict: fix first, narrowly.** Two changes before shipping. (1) Deny `script|expect|unbuffer|socat|pty.spawn` unconditionally, not only when the command mentions driver. Also record in ADR-010 that the TTY check is a strong speed bump, not a guarantee, since a written script run under a pty defeats it; the real guarantee is the future mod's `$.command.register`. (2) Fix submodule root resolution. Everything else can ship.
