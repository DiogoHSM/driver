# Review 6: live plan-graph mod (adversarial)

Date: 2026-10-28. Scope: ADR-011, `docs/research/05-mod-design.md`, `plugins/driver/mod/*`, `src/shared/*`, and the CLI paths the mod uses. Baseline: `npm test` 499/499, `npm run typecheck` ok, `claude plugin test` 25/25, `claude plugin validate` passed (icon warning only). Attacks ran on copies in the session scratchpad (`review2/web-waitlist`, git-initialised). The examples were not touched.

**Verdict: fix first.** The approval channel can be forged with two plain Bash commands that both guards (mod `tool.call` and node `protect-plan`) allow. The ADR calls this channel model-proof, and that claim is false today. The rest of the mod is solid.

## Accepted risks

- Script files, and any interpreter run on a file, stay unguarded (`node /tmp/w.mjs` is allowed). The guards only check the text of a Bash command. Under the same user, no verifier the model can run can tell the mod from the model. Gate approval is tamper-*evident* at best, so implement the `via:'mod'` alert.
- `PromptOrigin` `composer` also covers "a click on a transcript link". A link the model writes that runs `/driver approve` and that the person clicks would count as consent. Low risk, but say it in the ADR.
- The orphan write on SubagentStop stays in the shell hook. Without `node` on the GUI PATH, an orphaned block stays `in_progress`. The mod could fall back.
- The gate marker is chosen by the model: in `release`, a marker for an `implement` block passes (v1 semantics, shared with `gate-check.sh`).
- The 120k budget folds only done blocks: a mostly-open plan of 200 blocks measured 139k chars and falls back to the list.

## Untested behaviour

- Spawns: resumed spawns; a marker only in `description`; a retired or unknown marker block; parallel spawns; `next` throwing after `next.called`, which may re-run the spawn.
- Guard and CLI: Bash-guard bypasses beyond quoting and symlinks (none of the vectors above are in `protect.spec.ts`); a ticket with `exp` far in the future.
- Engine behaviour: whether `$.clock.every` from render is allowed, and whether the render state write happens in practice; whether the real engine registers the tools as `mcp__driver__*` (the harness assumes it).
- Approval UX: the slash-command path against a revision the person saw.
- Real Desktop origin for typed `/driver approve`, node discovery under the GUI PATH, lock contention with the 15 s timeout, hot-reload re-arm of the poller, and paint or scaling of a wide SVG.

**Updated verdict: fix first, narrower.** The textual guard now blocks every route I reported, but approval can still be forged in one Bash line through an inline interpreter (`node -e`) with concatenated strings. A plain `xargs cp` still writes into `.mod/`. A raw plan edit without `approvedVia` raises no alert.

Suggested fixes:
- Treat `node -e` / `-p`, `python -c`, `perl -e`, `ruby -e`, `eval`, `sh`/`bash -c` and `\| sh` as writes whenever a plan exists, not only when a protected name appears in the text.
- Unwrap `xargs` the way `env`/`exec` are unwrapped.
- Alert on **any** new approval that this session did not issue, whatever its `via` value. TTY approvals can be told apart by recording `via:'tty'` in the CLI.
