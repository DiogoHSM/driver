# Stack · DRIVER

## Language and runtime
- TypeScript 5 (strict, ES2022, NodeNext): all the plugin, CLI and mod logic.
- Node.js ≥ 20 (developed on 22): runtime of the CLI and hooks. Accepted risk: hooks require `node` on the user's PATH; the gate check has a pure `jq` fallback.

## Library and validation
- zod 4: `plan.json` schema, single source of truth for the types. `z.toJSONSchema` generates `schema/plan.v1.schema.json` for autocomplete in editors and non-TS tools.

## Build and tests
- tsup: single ESM bundle `dist/cli.js` with a shebang, committed (hooks do not depend on a build). The mod is loaded as source by the engine, without a bundle.
- vitest (`test/**/*.spec.ts`): node code and `src/shared` (SVG golden, layout, invariants, two-process concurrency). `tsconfig.node.json`.
- `claude plugin test plugins/driver` (`mod/test/*.test.tsx`): mod hooks and drawing on the terminal and desktop surfaces, with engine stand-ins. The root `tsconfig.json` extends `.claude-plugin/types/tsconfig.json` (generated by the engine on first load; gitignored) with `types: []`, which forbids `node:*` in `src/shared`.
- npm workspaces: private root with `plugins/*`.

## Platform
- Claude Code CLI ≥ 2.1.287: plugins, hooks (33 events), mods (early access API; recheck `claude-code.d.ts` on every release), semver `dependencies` in `plugin.json`, `claude plugin tag`.
- Mod: `Box/Text/Button/Select/Input/Markdown` elements everywhere; `Svg` only on Desktop, VS Code and mobile; `Raster` in the terminal. No `fs.watch`: polling with `$.clock`. No Node or DOM: writing only through the CLI's `$.process.run`. `claude-code.d.ts` pinned at 2.1.312.

## Command-line tools used by the hooks
- `jq` 1.7: gate check in one expression, fail closed if the file is unreadable.
- `git`: root resolution (`rev-parse --git-common-dir`) to always write in the main worktree.

## Development tools
- `claude plugin validate`: validates the marketplace and manifests.
- Linear (Personal team, DRIVER project): backlog. Plans in `.claude/plans/`.

## Decided not to use
- Native Claude Code tasks and the plan mode file as storage (ADR-009).
- `zod-to-json-schema` (zod 4 already generates JSON Schema).
- Undocumented desktop app session tools for orchestration (ADR-006).
