# Plan: DRIVER live diagram mod (plan graph panel)

## Context

`plan.json` v1 is implemented and committed (`6dfb08a`). ADR-009 foresees a core mod that mirrors the file and draws the graph beside the chat (SVG on Desktop/VS Code, Box/Text in the terminal), registers tools so the model can change state without writing JSON, and gives the user a gate approval channel that the model cannot invoke. The adversarial review of v1 left two points that only the mod closes: the model-proof approval channel (today it is a TTY, which can be bypassed with a pseudoterminal) and the `agent_id` → block mapping for the owner.

Expected result: working panel on Desktop and in the terminal, `mcp__driver__*` tools, `/driver` commands, owner claim on `agent.spawn` (also covers Workflow agents), tests with `claude plugin test` and vitest, ADR-011.

## Platform facts (gathered from `claude-code.d.ts` 2.1.312 and the plugin-authoring skill reference)

- Mod = a `register(on)` module listed in `hooks/hooks.json` under `"modules"`. No DOM and no Node: does not import zod or `node:*`; imports dependency-free TS files from the plugin; type-only imports are free.
- `Box/Text/Button/Select/Markdown/Input` on all surfaces; `Svg` (source ≤131,072 chars, `alt` required, `isInteractive` for `<title>` tooltips) only desktop/vscode/mobile; terminal has `Raster`.
- `$.fs.read/write/list/exists/stat` (mtimeMs, `resolve:true` gives `realPath`); no watch → `$.clock.every`. `$.process.run(argv, {cwd, env, stdin, timeoutMs})` without a shell; the doc marks it "CLI only": verify on Desktop at first load.
- `$.tool.register({isDeferred:false})` → `mcp__driver__<name>`, served by `on('tool.call',{tool})`. `$.command.register` → `/driver`, served by `on('command.run')` with no model turn; **`e.origin.kind === 'composer'` only when the user typed it**; `ui.press` is also initiated by the person. The model produces neither.
- `on('agent.spawn')` sees `e.prompt`/`e.description` and `await next(e)` returns `{ agentId }`; covers subagents of the Agent tool and Workflow agents (whose prompt may be a placeholder: fallback `currentPhase`).
- `$.plugin.root` is the plugin directory. State in `$.state` via `atom/read/update`, contract in `types/index.d.ts`; render never writes. `claude plugin test <dir>` runs `*.test.ts(x)`.
- Review finding: `protectPlan` compares paths with a case-sensitive regex; on APFS `.Claude/Driver/plan.json` gets through. Fix in node and in the mod (realPath + case-insensitive comparison).

## Design

### 1. File layout (in `plugins/driver`)

```
hooks/hooks.json          + "modules": ["../mod/index.tsx"]; the 3 shell hooks stay
mod/index.tsx             register(): session.start, wiring
mod/state.ts              typed atoms + poller (idempotent ensurePoller)
mod/cli.ts                runCli(args,{stdin}) → {ok,json,error}; node discovery (zsh -lc 'command -v node', cache in $.store, userConfig nodePath)
mod/pane.tsx              ui.render Pane: switch per surface
mod/render-terminal.tsx   Box/Text
mod/tools.ts              set_block_state, plan_ops, plan_status
mod/hooks.ts              agent.spawn, classic.SubagentStop, tool.call guard
mod/approve.ts            ticket + /driver approve
mod/test/*.test.tsx       claude plugin test
src/shared/               NO DEPENDENCIES (no zod, no node:*, no DOM)
  phases.ts               PHASES, BLOCK_STATUSES, phaseIndex, status glyphs/labels
  palette.ts              status → fill/stroke/text (mermaid.ts now imports from here)
  plan-doc.ts             structural interface PlanDoc (only fields readers use)
  view.ts                 project(plan) → PlanView; shapeCheck(raw)
  gate.ts                 gateVerdict(plan, promptText) (moved from src/hooks.ts)
  protect.ts              protectPlan + normalizeCommand (moved from src/hooks.ts)
  layout.ts               layout(view, opts) → coordinates
  svg.ts                  toSvg(layout, view, opts) → string
  rows.ts                 terminal row model
types/index.d.ts          declare module 'claude-code' { interface PluginState { driver: {...} } }
```

Toolchain: `schema.ts` re-exports `PHASES`/`BLOCK_STATUSES` from `shared/phases.ts` and builds `z.enum` on top; `src/hooks.ts` (node) imports `gate.ts` and `protect.ts`, a single implementation. A type test in vitest ensures `PlanV1` is compatible with `PlanDoc`. The current `tsconfig.json` becomes `tsconfig.node.json`; the new root `tsconfig.json` extends `./.claude-plugin/types/tsconfig.json` (generated by the engine on first load) with `include: mod, src/shared, types` and `types: []`, which makes any `node:` import in `src/shared` fail the typecheck. The vitest tests are renamed to `*.spec.ts` (`claude plugin test` collects `*.test.ts(x)`). tsup stays only for the CLI. Gitignore `.claude-plugin/types/` and `.claude/driver/.mod/`.

### 2. New CLI commands/ops required by the mod

| Command | Function |
|---|---|
| `driver where --json` | `{root, driverDir, planExists}`; root resolution in one place only |
| `driver apply --json` | reads `{ops[], expectedRevision?}` from stdin; applies everything under one lock, validates once, writes once, one event per op; earlier ids referenceable as `"$0"` |
| `--expect-revision N` | global flag mapped to `expectedRevision` of `mutate` |
| `block owner <id> <agentId> --from <prev>` | op `block.owner` (CAS: requires `in_progress` and `owner === from`), event `owner` |
| `gate approve <g> --via-mod` | reads nonce from stdin; validates ticket (section 8) |
| `status --json` | compact projection (`status` already exists; add `--json`) |

### 3. Data flow

- `session.start`: `where`; registers tools and commands; opens the panel only if `e.isInteractive && e.surface !== 'terminal' && planExists` (in the terminal it opens via `/driver`); `ensurePoller`.
- Poller: `$.clock.every(1000)` with the panel open, `5000` closed. Tick: `$.fs.stat` compares `(mtimeMs, size)`; only then reads, `JSON.parse`, `shapeCheck`, compares `revision`; writes to `$.state` only if it changed. After each mod write, an immediate tick. Hooks never use the cache: they always read fresh. `ensurePoller` is called from `session.start`, `command.run`, `ui.press`, `tool.call` and the first `ui.render` (timers die on hot reload).
- `$.state.driver`: `paths`, `load` (`none|ok|invalid{issues}|error`), `view: PlanView` (~150 bytes/block: id, title, phase, status, owner, reason, deps, req/test counts, verified, risk, retired, since), `ui` (focus, collapseDone, showRetired, selected, confirm), `detail`, `claims`.
- Panel states: no plan → `Input` with the folder name + **Initialize** button (`driver init`); invalid plan → errors from `validate --json` first, last good view dimmed with a "stale since rev N" banner; headless → never `ui.open`, tools/hooks/commands keep working.

### 4. SVG rendering (desktop/vscode)

Columns = phase swimlanes, subcolumns by depth within the phase (gates sit between phases; global layering would spread one phase across several columns). `layout.ts` is pure and deterministic:

Constants: `NW=176 NH=44 CG=40 RG=10 LP=14 LG=28 M=12 HH=34 LEG=30 MAXR=12 MINW=92 PX_PER_COL=8`.

1. Visible set: no retired items (unless `showRetired`), phase filter; `deps(b)` = `dependsOn` ∩ visible.
2. Local depth per phase: `d(b)=0` with no deps in the phase, otherwise `1+max d(dep)`; memoized DFS; a cycle drops the edge and marks `cyc`.
3. Column break: a depth group with `n>MAXR` becomes `ceil(n/MAXR)` physical columns; `S_p` columns per phase.
4. Lane expansion (`focus:'auto'`): only `currentPhase` expanded; adds neighbors while `naturalWidth ≤ bodyColumns·PX_PER_COL·1.25`; `'all'` expands everything; a collapsed lane has `MINW` with a stacked status bar and counts.
5. Geometry: `laneW_p = 2·LP + S_p·NW + (S_p−1)·CG` (or `MINW`); `laneX_0 = M`; `laneX_{p+1} = laneX_p + laneW_p + LG`.
6. Row order: single-pass barycenter (key = mean of the slots of already placed deps; tie-break by id); second pass for nodes without deps using successors.
7. `x = laneX_p + LP + col·(NW+CG)`; `y = M + HH + slot·(NH+RG)`.
8. `H = M + HH + maxSlots·(NH+RG) + LEG + M`; `W = laneX_5 + laneW_5 + M`; `<svg viewBox="0 0 W H">`, `width` not set (fits the slot).

Edges: cubic bezier from the source's right border to the destination's left, `k = max(20,(x2−x1−NW)/2)`; a backward edge (dep in a later phase) loops underneath, dashed red; for a collapsed lane it ends in a stub on the border. Pending dep: `#6b7280` 1.5; completed dep: `#9ca3af` opacity .5; edges of the selected block: `#2563eb` 2.

Nodes: `<g class="n s-<status>">`, rect `rx=6`, line 1 = id (mono 10px bold) + status glyph on the right, line 2 = title truncated at 25 chars (`…`). Glyphs: `○ ● ■ ◐ ✓ ↺` (not_started, in_progress, blocked, in_review, done, needs_rework), strokes 1/2.5 blue/2.5 red/2 amber/1.5 green/2.5 dashed orange. Opaque pastel cards with `#111827` text (legible in dark and light); lanes `rgba(127,127,127,.08)`. Badges: owner (pill with `main` or the first 6 chars of the agent id), red `!` on blocked/needs_rework, `▲` for high risk, retired with opacity .35 and struck-through title. `<title>` with id, title, status/since/by, owner, deps, reqs, tests, reason (XML-escaped). Gates: vertical line in the gap before `route` and before `release`, solid green + pill `✓ gate route · diogo` or dashed amber + pill `gate route · pending`. Current phase: highlight stroke and bold header; later phases at .6. Legend in the footer. A single `<style>` with short classes, integer coordinates, no inline `style=`.

Budget: ~4k fixed + ~520/node + ~75/edge (60 blocks ≈ 42k; 200 ≈ 131k). Ladder above 120k: (1) collapse `done` per phase into a `✓ 37 done` node with merged edges (same function as the toggle), (2) tooltips on the first line only, (3) terminal renderer with a warning. Cache by `(revision, ui, bodyColumns bucket)` in a module-level `Map`. `alt` = textual summary (phase, counts, gates).

### 5. Terminal rendering

Header per phase `▸ IMPLEMENT 5/9 done ● current` (folded phases on one line); gate lines `── gate route ✓ diogo 10-21 ──` / `── gate release ✗ pending · /driver approve release ──` (yellow). Each block is `Button plain key=B-xxx`: `{indent}{glyph} B-004 {title…} {owner} ← B-003,B-007 +2` (only pending deps; indent 2×depth, max 3). `room = viewport.rows − 4`; `auto` focus expands only the current phase; overflow windows around the selection with `↑ 4 more` / `↓ 9 more`.

### 6. Interaction

Buttons with hotkeys: `1-6` phase, `a` all, `d` hide done, `r` retired, `e` export Mermaid, `g` approve pending gate (only when the next phase requires it), `x` close detail, `i` init. Selection: one button per row in the terminal; a `Select` of the visible blocks below the SVG on desktop/vscode (presses on the SVG do not reach the plugin). Detail: the handler rereads `plan.json` and `blocks/<id>.md` (6k chars) and writes `detail`; shows fields and the doc as `Markdown`; the poller updates when `revision` changes. Approving in two steps: button → `ui.confirm` → "Approve gate route at revision 42 (baseline 1)?" with **Approve** (`y`, primary) and **Cancel** (`n`); `ui.press` is initiated by the person. Export: runs `export mermaid`, shows the path and offers **Copy** (`$.ui.copy`).

### 7. Tools for the model (`isDeferred:false`)

Errors: exit 1/2 → `{deny: "DRIVER refused: <stderr .error>"}` with the reducer's reason; spawn failure/15 s timeout → `{deny: "DRIVER CLI unavailable: …; fallback: driver via Bash"}`; success → short text `ok rev 43; created B-012`. Always `--actor model:${agentId ?? 'main'}`, `--root`, `--json`, `--expect-revision` when given.

- `set_block_state {block:^B-\d{3,}$, status: in_progress|blocked|in_review|done|needs_rework, reason?, owner?, expectedRevision?}` → `block status`. Never exposes `not_started` or `--force`; pre-checks `reason` in blocked/needs_rework.
- `plan_ops {ops: Op[] (1..25), expectedRevision?}` with `block.add`, `block.set`, `req.add`, `decision.add`, `block.retire|req.retire`, `phase.advance`; `"$0"`/`"$1"` reference created ids; goes via stdin to `driver apply --json`; atomic.
- `plan_status {scope?: summary|phase|block, phase?, block?}`: read-only, served by the mod from a fresh projection, no spawn; returns phase, gates, counts, **ready** (not_started with deps done up to the current phase), in progress with owners, blocked with reason; `block` returns the record and 1.5k of the doc.

The tool descriptions say why to prefer them over Bash (schema in the prompt, no quoting, structured errors, automatic actor, atomicity, fewer tokens, panel updates). Phase skills will say "use `mcp__driver__*` when listed; CLI is the fallback".

### 8. Mod hooks

- `agent.spawn` (guard, `.catch` fail-closed): fresh read (no plan → `next`; unreadable → deny); marker `DRIVER-BLOCK:\s*(B-\d+)` in `prompt`, then `description`, fallback `currentPhase`; `gateVerdict` (the same function as the node hook; closes the gap for Workflow agents); containment: an `in_progress` block with owner ≠ main/this orchestrator and `$.agent.list()` shows the owner running → deny; `r = await next(e)`; no `agentId` → no claim; claim: `not_started|needs_rework|blocked` → `block status … in_progress --owner <agentId>`; `in_progress` by `main`/empty/non-running agent → `block owner <id> <agentId> --from <current>`; `done|in_review` → nothing. Records `claims[agentId]`; failure after spawn → `$.ui.toast` + `$.session.append` warning the orchestrator.
- `classic.SubagentStop`: `await next(e)` (the shell hook does the orphan handling; do not contend for the lock), removes `claims`, tick, toast if it became `blocked`.
- `tool.call` on `Write|Edit|MultiEdit|Bash`: calls `shared/protect.ts::protectPlan` (the same function as node) with an extra step for file tools: `$.fs.stat(dir,{resolve:true}).realPath` + case-insensitive comparison with `driverDir`. Rationale: the shell hook fails open without `node` on the GUI app's PATH, and only the mod resolves symlinks/case. Apply the same realPath/case fix in `src/hooks.ts`. `PROTECTED_FILE` now covers `.claude/driver/.mod/`.

### 9. Commands: one `driver` registration with argument parsing

- `/driver` | `/driver status`: `ui.open({id:'driver', title:'DRIVER', columns:72})` + status text.
- `/driver export`: `export mermaid`, returns the path and a ```mermaid block.
- `/driver init <name>`.
- `/driver approve <route|release>`: (1) requires `e.origin.kind === 'composer'`, otherwise answers "the approval has to be typed by you" (the panel button is the universal path); (2) reads the plan, `R = revision`; (3) `nonce` = 32 bytes from `crypto.getRandomValues` in hex; (4) `$.fs.write(<driverDir>/.mod/ticket.json, {gate, revision:R, sha256(nonce), exp: now+15s})`; (5) `runCli(['gate','approve',gate,'--via-mod'], {stdin: nonce})` with `--actor user:<git user.name>`; (6) the CLI reads and **deletes** the ticket first (one-shot), checks `exp`, `gate`, `plan.revision === R`, compares `sha256(stdin)` with `timingSafeEqual`, applies `gate.approve` as the user actor; (7) reply + `context: ["User approved gate route via /driver at rev R"]`.

Why the model cannot forge it: it does not produce a composer `command.run` or a `ui.press`; `gate approve` via Bash is already denied; bypassing with a script in a file requires writing to `.claude/driver/.mod/`, which Write/Edit and Bash write verbs deny; reading the ticket does not help (it is a hash); the nonce goes via stdin (env shows in `ps eww`, argv in `ps`). The channel is as strong as the protection of `plan.json` itself, better than the TTY. Rejected: plain nonce in a file (readable, race), token in env + `$.store` (visible).

- `claude plugin test` (`mod/test/*.test.tsx`), loop `['terminal','desktop']`, stand-ins for `fs.*`, `process.run` (records argv/stdin), `command.register`, `tool.register`, `ui.open`, `agent.spawn`, mocked clock: terminal shows `B-004`, glyph `●`, header `IMPLEMENT`, `gate route ✓`, press opens detail; desktop has `Svg` with `alt`, `B-004`, `<title>`, size < 120k; a 200-block plan under budget with `✓ … done`; no plan → **Initialize** → argv `init`; invalid plan draws issues; `set_block_state` argv; exit 1 → deny with message; `plan_ops` stdin with `$0`; `plan_status` without `process.run`; `agent.spawn` denies with a closed gate, claims with `--owner a1`, transfers with `--from main`; `/driver approve` with plugin origin → refused with no write, composer → ticket written and nonce only on stdin; `tool.call` Write on `.Claude/Driver/plan.json` → deny.

## Risks and first-load checks

1. `$.process.run(['node',…])` may fail with the GUI app's PATH: discover node via `zsh -lc`, cache in `$.store`, `userConfig nodePath`. Degradation: tools return to the model the command to run via Bash; `/driver approve` falls back to the TTY.
2. Which `e.origin.kind` a `/driver approve` typed on Desktop carries; if it is not `composer`, keep the refusal and use the panel button. Never widen to `sdk` blindly.
3. Do `crypto.getRandomValues`/`crypto.subtle` exist in the mod environment? Fallback: `openssl rand -hex 32` and the CLI does the hash.
4. Does a wide SVG scale or scroll? Does the pane scroll a tall SVG? Does `<title>` show up? Are `PX_PER_COL=8` and 6.4 px/char right?
5. Does `session.start` run again after hot reload? Can render start a timer?
6. Does `claude plugin validate` accept `hooks` + `modules` in the same `hooks.json`? Can a module import `../src/shared/*.ts`? Does the engine leave the root `tsconfig.json` alone?
7. Does `claude plugin test` ignore `*.spec.ts` and `node_modules`?
8. Order of the shell `PreToolUse` vs `agent.spawn`; is `agentId` present for local Workflow agents?
9. Lock shared between mod and Bash writes (5 s retry): `process.run` timeout at 15 s; `LockTimeoutError` becomes a retryable deny.
10. The mods API is early access: pin `claude-code.d.ts` 2.1.312 and recheck on every release.
