# Plan: DRIVER plan graph format (`plan.json`)

## Context

DRIVER is a Claude Code plugin that enforces the Discover · Route · Implement · Validate · Evolve · Release method. ADR-002 defines the central artifact as a graph of blocks with state; ADR-009 (Proposed) fixes the location `.claude/driver/plan.json`, but the format does not exist yet. Everything depends on it: the diagram mod, the gate hook, requirement→block→test→release traceability, packs.

Premises accepted by the user in this session:
- TypeScript for plugin and mod.
- `plan.json` versioned in the git of the user's project; history via commits, no `plan-v1.json`.
- v1 scope: phases, blocks, states, dependencies, linked requirements, provider per block, gate flags. Out: cost, epics, automatic impact analysis (reserve optional fields).

Fact that drives the design: `plan.json` is in git, so **every worktree has a stale copy**. Writes must go to the main checkout, through a single writer.

Deliverable: zod schema + generated JSON Schema, TS library (pure reducer + I/O adapter), `driver` CLI, gate hooks, two examples (web and video), Mermaid exporter, ADRs. No mod and no skills in this round.

## Design

### 1. Layout in `.claude/driver/` (created by `driver init`)

```
plan.json                 committed, canonical snapshot
events.jsonl              committed, append-only ledger (.gitattributes merge=union)
log/REL-1.jsonl           committed, journal rotated at each Release
blocks/B-001.md           committed, long text per block (Spec, Acceptance criteria, Notes, Handoff)
requirements/R-001.md     committed, optional
decisions/D-001.md        committed, Evolve decisions and re-baselines
discover/{interview,assumptions,non-goals}.md
exports/plan.mmd          gitignored, regenerated by `driver export`
.lock/ .tmp/              gitignored
```

The markdown path is implicit from the id (`blocks/<id>.md`); the JSON does not store the path.

### 2. Schema (zod is the source; types below)

```ts
type PhaseId = 'discover'|'route'|'implement'|'validate'|'evolve'|'release';
type BlockStatus = 'not_started'|'in_progress'|'blocked'|'in_review'|'done'|'needs_rework';
interface Actor { kind: 'model'|'user'|'hook'; id: string }

interface PlanV1 {
  $schema?: string;
  schemaVersion: 1;
  project: { name: string; packs: string[]; createdAt: string };
  revision: number;        // +1 on every write (CAS and change detection by the mod)
  baseline: number;        // 0 until Gate 1; +1 per re-baseline in Evolve
  updatedAt: string;
  currentPhase: PhaseId;   // denormalized for the hook
  nextId: { R: number; B: number; D: number; REL: number };
  gates: { route: Gate; release: Gate };          // key = phase the gate releases
  requirements: Record<string, Requirement>;      // 'R-001' → ...; O(1) lookup in jq, stable diffs
  blocks: Record<string, Block>;                  // 'B-001' → ...
  baselines: BaselineEntry[];
  releases: Release[];
  ext?: Record<string, unknown>;                  // namespace per pack: ext['driver-web']
}
interface Gate { approved: boolean; approvedAt?: string; approvedBy?: string; atBaseline?: number; revokedAt?: string; revokedReason?: string }
interface Retirement { at: string; decision: string; reason: string }
interface Requirement { title: string; kind: 'functional'|'nonfunctional'|'constraint'|'non-goal'; source: 'user'|'assumed'; ref?: string; retired?: Retirement; ext?: Record<string, unknown> }
interface Block {
  title: string; phase: PhaseId;
  status: BlockStatus; statusSince: string; statusBy: Actor; statusReason?: string;  // required in blocked and needs_rework
  owner?: string;                 // agent_id while in_progress
  dependsOn: string[]; requirements: string[];
  provider?: { capability: string; provider: string; access: 'cli'|'mcp'|'api'; credentials?: string[] };  // env var names, never values
  artifacts: string[];            // paths relative to the repo
  tests: { ref: string; layer: 'unit'|'integration'|'e2e'|'visual'|'perf'|'security'|'acceptance'|'manual'; result: 'pass'|'fail'|'unknown'; at?: string; commit?: string }[];
  verification?: { passes: boolean; at: string; by: Actor; commit?: string };   // ralph style
  risk?: 'low'|'medium'|'high';
  retired?: Retirement;           // removed by Evolve; never deleted
  ext?: Record<string, unknown>;
}
interface BaselineEntry { n: number; at: string; decision: string; reason: string; added: string[]; retired: string[]; changed: string[]; reqAdded: string[]; reqRetired: string[] }
interface Release { id: string; version: string; at: string; baseline: number; commit: string; blocks: string[] }
```

Blocks exist in every phase (e.g. `B-001 Interview` in discover, `B-002 Plan` in route), so the diagram shows the whole method. An empty phase is allowed (proportionality, ADR-008); gates still apply. Future fields reserved as optional: `estimate`, `parent` + `epics`, `impact`. Readers ignore unknown fields; `schemaVersion` only goes up on a breaking change, with `driver migrate`.

### 3. State machine

| From → To | Who | Requires |
|---|---|---|
| not_started → in_progress | model (tool) | all `dependsOn` in done (user may `--force`); writes `owner` (works as a claim under lock) |
| in_progress → in_review | model | non-empty `artifacts` and a Handoff section in the md |
| in_progress → blocked | model, hook | `statusReason` |
| blocked → in_progress | model, user | note in the event |
| in_review → done | model (reviewer), user | `verification.passes === true`; no `fail` test |
| in_review → needs_rework | model, user | `statusReason` |
| done → needs_rework | model (Validate), user | `statusReason` |
| needs_rework → in_progress | model | |
| any → not_started | user only (`driver rebaseline`) | decision id `D-xxx` |

The only automatic transition in v1: the `SubagentStop` hook moves to `blocked` ("agent ended without handoff") the block still `in_progress` whose `owner` is the agent that stopped. Every transition stamps `statusSince/statusBy/statusReason` and appends a line to `events.jsonl`: `{seq, ts, actor, type, block, from, to, reason?, revision}`. Full history only in the ledger and in git.

### 4. Gates

- Approval **only by the user**: `/driver approve <route|release>` (command with no model turn; in headless, `driver approve` in the user's terminal). Writes `atBaseline`.
- Automatic revocation by the writer: `release` is revoked on re-baseline, when any block leaves `done`, or when the phase moves back from evolve/release; `route` is revoked when the phase moves back to discover or when a requirement is added/retired.
- `currentPhase` only advances through `driver phase advance`, which refuses to cross an unapproved gate. Moving back is always allowed, with a reason.
- `PreToolUse` hook on `Agent|Task|Workflow`: phase skills prefix agent prompts with `DRIVER-BLOCK: B-012`; the hook infers the block's phase (fallback: `currentPhase`) and denies if the corresponding gate is not approved. A single `jq` expression; missing plan.json → allow (project does not use DRIVER); unreadable → deny (fail closed).
- `PreToolUse` hook on `Edit|Write|Bash`: denies direct writes to `plan.json` and denies `driver approve` coming from the model via Bash.

### 5. Writing and concurrency

- One TS core (`driver-core`: pure reducer + node adapter) used by the `bin/driver` CLI and, later, by the mod tools (`set_block_state`, `plan_ops`). The same lock implementation on every path.
- Protocol: (1) root = main worktree via `git rev-parse --git-common-dir`, never the agent's worktree; (2) lock via `mkdir .lock` with pid+ts, stale after 30 s with a dead pid, retry every 50 ms up to 5 s; (3) read, check optional `expectedRevision`, apply mutation and transition; (4) `validatePlan`, reject on error; (5) `revision++`, deterministic serialization (sorted keys, 2 spaces), `.tmp` + fsync + rename; (6) append event, release lock.
- The orchestrator is the normal writer; subagents return a structured result. When a subagent needs to write, it uses the CLI, which resolves the root via git. Worktree branches never touch `plan.json` (the hook blocks it), so merging does not conflict.
- Mod (future): `$.clock.every(1000)`, redraws only if `revision` changed.

### 6. IDs and traceability

`R-001`, `B-001`, `D-001`, `REL-1`; allocated only by the writer, under lock, from `nextId`; never reused; retired items stay in the file with `retired`. Chain: `R` → `block.requirements` → `block.artifacts` + `block.tests` → `verification` → `releases[].blocks`. Retiring a requirement or block cites a `D-xxx`. `driver validate` detects duplicate ids after a human merge; `driver renumber` repairs them.

### 7. Validation (`validatePlan`, errors and warnings)

zod shape and id formats; no duplicates; `nextId` greater than the existing maximum. `dependsOn`/`requirements` references exist; no cycles (Kahn); no depending on a block of a later phase. `statusReason` present in blocked/needs_rework; `owner` only in in_progress. Phase beyond discover ⇒ `gates.route.approved`; phase release ⇒ `gates.release.approved` and all active blocks from implement to evolve in done, active requirements covered by a done block with `verification.passes`. Requirement coverage: warning in Discover, error from Gate 1 on. `blocks/<id>.md` exists; `credentials` match `^[A-Z][A-Z0-9_]*$`. Runs inside every write, in `driver validate` (exit codes) and in `driver validate --replay` (folds `events.jsonl` and compares with the statuses).

## Verification

```bash
npm test && npx tsc --noEmit
node plugins/driver/dist/cli.js validate examples/web-waitlist
node plugins/driver/dist/cli.js validate examples/video-explainer
node plugins/driver/dist/cli.js export mermaid examples/web-waitlist   # check exports/plan.mmd
bash plugins/driver/hooks/gate-check.sh < test/fixtures/hook-input-release-unapproved.json   # expects deny
```

Required tests: two processes writing at the same time neither corrupt the file nor duplicate ids; an invalid transition is rejected and does not change the file; re-baseline revokes `gates.release`; `validate --replay` matches the statuses.

## Risks and pending items for the next phase (mod)

- `$.fs` capabilities (exclusive create, rename, stat) not confirmed; check in `claude-code.d.ts` before the mod. Fallback: the mod calls the CLI via `$.process.spawn`.
- Not confirmed whether a subagent in an isolated worktree can call a tool registered by the mod; the fallback is the CLI.
- `DRIVER-BLOCK:` is a convention; an agent without the marker falls back to `currentPhase` (safe, but does not detect a wrong label).
- Human merge of branches can duplicate ids; `renumber` repairs, does not prevent.
